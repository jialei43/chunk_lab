从列表页抓取文件

给一个列表页地址，自动翻页并下载其中的文档。默认遵守 robots.txt、 串行请求并带间隔——抓取公开站点时，把对方站点压出问题比慢几分钟严重得多。 文件存到数据目录的 downloads/，可在下方选中送去解析入库。

逗号分隔的扩展名。
很多站点的下载地址不带扩展名（如 /pdf/2401.12345、download?id=9）， 只按扩展名会全部漏掉。填正则可补上，与扩展名取并集。
列表页返回 JSON 而非 HTML 时填这里（很多站点的列表其实是接口）。 点号分隔的字段路径，指向文件地址所在的字段。填了它，下方的翻页与详情页选择器就不再使用。
JSON 里多是相对路径，拼上前缀才能下载。
接口靠改参数翻页，没有「下一页」链接可循。
留空则只抓当前这一页。也可用下方选择器精确指定。
CSS 选择器，优先级高于文字匹配。
附件在详情页时填写，抓取器会先进详情页再找文件。
防止翻页成环时无限抓取。
0 表示不限。建议先设个小值试跑。
两次请求的全局最小间隔，与并发数无关。 这才是抓取速度的主要决定因素：想快就调小它，代价是对方站点压力线性上升。
只对大文件传输有效。若耗时主要花在请求发起上（详情页多、文件小）， 并发不会提速——请求频率被下面的间隔锁死。实测 50+ 详情页、6 个 1MB 文件时， 并发 4 与串行耗时相同。设为 1 即完全串行。
仅在确认自己有权抓取该站点时才关闭。
建议先试跑，确认抓到的是想要的文件再正式下载。
