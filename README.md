# chunk-lab

RagFlow MinerU 切分逻辑的离线实验室。用于持续发现切分缺陷、量化改动效果、防止回归。

## 与 ragflow 的关系

**本仓库完全独立，不属于 ragflow 的版本管理。**

- `/Users/jialei/Desktop/RagFlow/` 本身不是 git 仓库，唯一的仓库是它下面的 `ragflow/`（以及 `lzcj_web/`）。
- 本目录与它们平级，物理上不在任何一方的工作树内。在 `ragflow/` 下执行 `git status` / `git add -A` **看不到本目录的存在**——不是靠 ignore 规则挡住，是根本不在范围内。
- 本实验室对 ragflow **只读**：导入它的切分代码、读取 MinerU 产物，不写入任何文件，不安装任何依赖，`pyproject.toml` 与 `uv.lock` 保持零改动。

## 数据目录（在仓库之外）

语料、历史轮次、报告、MinerU 解析产物全部存在**仓库之外**，默认 `~/MinerU/chunk_lab/`：

```
~/MinerU/chunk_lab/
├── corpus/       语料（含 middle.json，实测 20MB+）
├── runs/         历史轮次快照与切分文本
├── reports/      Markdown 评估报告
├── baselines/    基准指针
├── mineru_out/   MinerU 解析产物（与生产的输出目录分开）
└── uploads/      上传的原始文件
```

这样安排是因为这些数据体积大且持续增长，留在仓库内会让 IDE 索引整个项目时明显变慢。仓库内只保留代码（约 500KB）。

修改位置，两种方式，优先级从高到低：

```bash

CHUNKLAB_DATA_DIR=/path/to/data ./run.sh eval

# 2. 本机配置文件（复制 labconfig.example.json 为 labconfig.json，不入版本管理）
{ "data_dir": "~/MinerU/chunk_lab" }
```

当前生效的路径在 Web 控制台的「切分配置」弹层顶部可以看到。

## 运行：Web 控制台（推荐）

```bash
./serve.sh start     # 后台启动
./serve.sh stop      # 停止
./serve.sh restart   # 重启
./serve.sh status    # 查看是否在运行
./serve.sh log       # 跟随查看日志

./run.sh serve       # 前台运行（Ctrl+C 停止）
```

启动后打开 http://127.0.0.1:5099　换端口：`CHUNKLAB_PORT=6000 ./serve.sh start`

**改代码即时生效**，不必手动重启：服务默认开启热加载，改 `labkit/` 下的 Python 或前端页面后约 2 秒自动重启（实测）。不需要时用 `./run.sh serve --no-reload` 关掉，可省下重载器多起一个进程的开销。

`serve.sh` 以端口占用而非 PID 文件判断服务状态，并且停止时会结束**全部**占用该端口的进程——热加载模式下 Flask 重载器有父子两个进程，只杀子进程的话父进程会立刻把它重新拉起，看着停了实际没停。

四个页面覆盖日常全部操作：

| 页面 | 作用 |
|---|---|
| **概览** | 一键运行评估；轮次对比（任选两轮，非只能比基线）；趋势图看各类问题随轮次的累计变化；历史轮次列表可设基准／打备注／删除；问题分布与逐样本统计 |
| **切片预览** | 选一个样本，逐块查看实际切分结果，有问题的切片按严重度标色并附证据 |
| **语料库** | 当前语料清单 |
| **添加语料** | 扫描本机 MinerU 产物，勾选导入。已导入的自动标灰，可按文档名筛选 |

顶栏的 token 预算与子分隔符对评估和切片预览同时生效，改完直接重跑即可做参数对比。

服务只监听回环地址，是开发时工具。基于 ragflow 虚拟环境里已有的 Flask，前端零构建、无外部依赖。

## 运行：命令行

```bash
./run.sh ingest                    # 把本机 MinerU 产物导入语料库
./run.sh eval                      # 全量评估，出报告
./run.sh baseline                  # 建立回归基线
./run.sh eval --compare            # 改代码后：与基线比较指标升降
./run.sh eval --compare --set-baseline   # 确认改善后固化为新基线
./run.sh smoke <产物> <文件名>      # 单产物连通性调试
```

常用选项：

| 选项 | 说明 |
|---|---|
| `--case <id>` | 只评估指定样本，可重复，用于针对单个文档快速迭代 |
| `--children-delimiter` | 父子分块分隔符，**对切分粒度影响极大**，见下文 |
| `--chunk-token-num` | 覆盖 token 预算 |
| `--top N` | 每类问题展示 N 条样例证据 |

全量评估 13 个样本、5608 个原始块约 **14 秒**——同样的内容走真实解析要几十分钟，这个差距就是整套方案能持续迭代的前提。

`run.sh` 固定使用 `ragflow/.venv/bin/python` 的绝对路径，不依赖当前终端激活了哪个虚拟环境，且**绝不使用 `uv run`**（避免触发 `uv.lock` 解析并静默改写环境）。

## 设计要点

离线驱动**不写任何 stub**，直接构造真实的 `MinerUParser` 并调用生产函数 `chunk_mineru_blocks`，保证离线结论与线上行为零偏差。三条依据均已在 ragflow 源码中核对：

1. `MinerUParser.__init__` 只赋值属性、不做网络调用，可无参构造；
2. `chunk_mineru_blocks` 内所有 `crop` 调用点都有 `page_images` 守卫，不提供页面图像即走"无截图"分支，与生产的 Office 路径行为一致；
3. `tenant_id` 传 `None` 时 `get_vision_model` / `get_chat_model` 直接返回 `None`，不加载 LLM、不 import `api.db`、不连数据库——因此离线结果确定可复现。

## 阶段一：保真度验证结论（已通过）

用 `tmp/pdfs/mineru_two_column_e2e_output/` 的双栏 PDF 产物离线重放，与历史生产 e2e 结果 `mineru_two_column_e2e_chunks/summary.json` 逐块比对：

- 喂给切分器的 blocks 完全一致（23 个，`text_level` 分布相同），确认产物层无偏差；
- 父块正文与生产 chunk 逐字吻合（如 `> 2 评估方法` + `[P03] 本样例采用 A4 纵向页面…`）；
- 唯一差异是面包屑分隔符（生产为换行、当前代码为 ` > `），属 summary.json 是历史产物、面包屑格式后来改过的代码演进，非离线偏差。

PPTX 路径同样验证通过（40 chunk，含 9 个表格，位置/页码/面包屑齐全）。

### 关键发现：`children_delimiter` 是切分粒度的主开关

同一份产物，仅改这一个参数，结果差异巨大：

| `children_delimiter` | chunk 数 | 平均长度 | 说明 |
|---|---|---|---|
| 空 | 14 | 127 | 每个原始段落独立成块 |
| `\n` | 14（子块） | 128 | 5 个父块，按换行拆成 14 个子块 |
| `‡`（正文中不存在） | 5 | 306 | 子拆分不切割，即父块粒度 |

机制在 [`mineru_chunker.py:1494-1498`](../ragflow/rag/app/mineru_chunker.py#L1494) 的合并边界判定：默认模式下"同标题的不同原始段落也必须独立成块"，父子模式下只有标题变化才断开。

两个必须记住的契约：

- **离线驱动必须复刻 `naive.py` 的 `children_delimiter → 正则` 转换**（含 `unicode_escape` 还原与反引号自定义分隔符），否则同一份产物会得到与生产迥异的结果；
- **父子模式下返回的全部是子块**，父块全文挂在 `mom_with_weight` 字段上。评审器必须据此区分口径，否则会把子块的短长度误判为切分过碎。

## 阶段二～三：检测器、语料库与回归防护（已完成）

### 语料库

13 个样本、5608 个原始块，覆盖 PDF（双栏／法律／年报／专利）、PPTX、DOCX、XLSX。

同一文档的重复解析副本只收一份，但**同源不同 backend 的产物刻意保留为对照**（`law_bill_hybrid` 137 块 vs `law_bill_vlm` 111 块）——块数差异这么大，切分逻辑对它是否鲁棒本身就该被测。

### 检测器

12 个规则检测器，全部在 `detectors.py` 的 `ALL_DETECTORS` 登记表中，新增只需追加一项。

严重度分三档：`high` 内容层缺陷（截断、表格破损、乱码、噪声、字间空格）、`medium` 质量问题（超长、标题孤块、重复、markdown 残留、图片空壳）、`low` 体验问题（面包屑丢失、定位缺失）。

### 首轮调优：651 → 258 条

首轮误报率很高，逐条判读证据后修正，这个过程本身是检测器设计的必要环节：

| 问题 | 修正 |
|---|---|
| 项目符号字符类漏了 `●` 等 | 补全符号表，并对"多行且末行短"的罗列结构豁免整句判据 |
| 458 条碎片块淹没其他信号 | 同一样本碎片超过 20 个时聚合成一条汇总 |
| 封面块被判缺面包屑 | 定位首个带面包屑的 chunk，其之前的封面区整体豁免 |

调优后剩余命中大部分为真问题。铁证级样例（`annual_cnipa #54`）：

> …新加坡、匈牙利、西班牙、法国、丹麦、澳大利亚和摩洛哥等国家知识产权机构以及欧盟知识

"欧盟知识"后面应是"产权局"，是明确的跨块截断。

### 回归防护：运行历史

每次评估都存成**不可变快照**（一个 run），任意两轮之间都能对比。基线不再是一份独立数据，只是**指向某一轮的指针**——因为单一基线文件一旦更新，之前的历史就没了，无法回答「这几次改动累计效果如何」「哪一次引入了这个回归」。

```bash
./run.sh eval --label "修复 DOCX markdown 残留"   # 跑一轮，自动存入历史
./run.sh runs                                    # 看全部历史轮次
./run.sh runs --compare baseline latest          # 对比任意两轮
./run.sh baseline <run_id>                       # 把某轮设为基准（不必重跑）
```

轮次引用支持三种写法：`baseline`（当前基准）、`latest`（最新一轮）、具体 `run_id`。

**每轮记录代码指纹**——对 `mineru_chunker.py` / `mineru_parser.py` / `mineru_noise.py` 做联合内容哈希。这比 git commit 更准：改了没提交时 commit 不变，只有哈希会变。没有它，历史轮次不知道对应什么代码状态，对比就失去意义。

**对比前自动校验可比性**。参数或语料不同的两轮，数字并列会直接导致误判，因此会显式警告：

```
⚠️  这两轮不完全可比：
    · token 预算不同（512 vs 256），切分粒度本就不同，数字不能直接归因于代码改动
    · 两轮的被测代码完全相同，指标差异并非来自代码改动
```

这两条合起来就说清了：那次「劣化 +16」根本不是代码问题。

### 切分文本快照：为什么必须存

每轮同时保存**当时的切分文本**（`runs/<id>.chunks.gz`）。这不是可选项：离线驱动调的是**当前**代码，代码一改，旧轮次的切分结果就再也无法重现。不存下来，历史轮次只剩统计数字，看不到那时文本被切成了什么样。

体积可控：3272 个切片的完整正文，gzip 后约 **335 KB**，跑 20 轮才 6.7 MB。

有了它才能做**文本级对比**——问题数只能说明"多了 6 条截断"，文本对比才能说明"边界从哪挪到了哪"。实测 token 512→256：

```
切片 89 → 97，内容未变 84，变化 13
[修改] #4 → #4
  前：附件4\n<table>…
  后：附件4（分片 1/2）\n<table>…
```

表格被拆成了「分片 1/2」「分片 2/2」，一眼可见。配对同样按内容而非序号——按序号比会把 89 个切片几乎全算成变化。

切片预览页也可切换数据来源：**实时切分（当前代码）** 或**任一历史轮次的快照**。

存储上，`runs/*.json` 是报告（含 findings 明细），`runs/*.chunks.gz` 是切分文本，两者体积大不入库；`runs/index.json` 是轻量索引（含各轮各检测器命中数，**入库**），所以指标趋势可以长期追溯。

对比同时输出**命中数**与 **chunk 数**两个维度，缺一不可。实测把 `chunk_token_num` 从 512 降到 256：

```
xlsx_9sheet    命中 0→0 (+0)    chunk 65→208 (+143)
```

命中数完全没变，切分粒度却暴增 3 倍。只盯问题数会彻底漏掉这类回归。
